# 瀚霖创作引擎 · 设计交付与下一步计划

> 版本：v1.1 ｜ 日期：2026-07-25 ｜ 状态：待产品、设计、研发共同确认
>
> 关联：[产品 PR](./瀚霖创作引擎-产品PR文档.md)、[全量产品体验与页面设计方案](./瀚霖创作引擎-全量产品设计方案.md)、[UI/UX 规范](./瀚霖创作引擎-UIUX规范.md)。本计划先验证 M0 小说闭环的可用性；小说转剧本作为 M1 核心路径与小说内测并行设计，在领域契约和来源溯源通过验收后实施。独立剧本、协作和开放 API 留在后续阶段。

## 1. 本轮产出与未决事实

本轮已形成三个可评审产物：产品 PR v2.4 的体验决策、全量页面/导航/路由架构、UI/UX 实现与 QA 规范。它们解决“用户从哪里开始、在哪里继续、风险出现在哪里、不同阶段看见什么”的产品设计问题。

尚未完成真实用户验证。PR、现有 Studio API、当前单页工作台和用户提供的截图足以提出假设，但不足以证明用户会理解“事实变化”“定稿恢复”或作品级导航。因此，下一阶段的第一个交付不是高保真视觉稿，而是树测和中保真可点击原型。

## 4. 原型测试执行

参与者为 5-8 名中文小说作者，其中至少 3 名有连载或中长篇经验，至少 2 名使用过通用 AI 写作工具。每次远程主持 45 分钟，要求口述思考；主持人不解释“事实层、Run、状态机”等术语。

测试任务：

1. 从主题创建一部小说，修改一个角色设定后进入第一章。
2. 确认章节计划，生成两个草稿并恢复第一个草稿。
3. 处理一条角色变化和一条时间冲突，完成定稿。
4. 遇到模拟的摘要更新失败后继续完成，并导出已定稿章节。
5. 选择一部已定稿小说，确认改编简报；解释一项角色合并取舍，生成第一个场景并从剧本回到原作证据。

记录每项的完成/失败、耗时、错误、口述困惑和绕行路径；测试后完成 10 题 SUS。优先按严重度处理：阻断任务或可能误操作历史内容为 P0；反复造成迟疑为 P1；视觉偏好为 P2。

## 5. 研发切片与责任边界

| 切片          | 页面/组件                            | 前端责任                           | 后端依赖                         | 不在本切片中               |
| ------------- | ------------------------------------ | ---------------------------------- | -------------------------------- | -------------------------- |
| S1 全局起步   | `AppSidebar`、P01/P02/P03            | 新导航、作品列表、创建 Sheet、空态 | 项目列表、创建、运行状态         | 剧本、模板市场、团队       |
| S2 项目上下文 | `ProjectNav`、P05/P06                | 项目壳、蓝图/计划编辑、影响提示    | 项目概览、蓝图、计划、恢复影响   | 富文本、关系图             |
| S3 写作闭环   | P07、`WritingEditor`、`ContextPanel` | 草稿/作者修订、保存态、章节定位    | 草稿、修订、事实变化、审校、定稿 | 全自动整书、LLM 软评审     |
| S4 恢复与交付 | P08/P09/P10/P11                      | 裁决、任务、diff、导出 Sheet       | 事件、恢复、审校、导出           | DOCX/Final Draft、发布直连 |
| S5 M1 内测    | P17、埋点与帮助                      | 可用性修订、错误态、窄屏走查       | 成本/权限/合规数据中已存在部分   | 协作、开放 API             |
| S6 小说转剧本 | P13、P12 改编场景工作台               | 改编简报、来源快照、取舍、场景对照 | 改编领域契约、快照、映射、可恢复 Run | 独立剧本、多人审稿、全季自动生成 |

前端仅使用 NestJS 经 ts-rest 暴露的 Studio 契约；Python Runtime 地址、密钥、模型参数与内部任务实现不进入浏览器。所有 UI 的“已完成”“可恢复”“已定稿”必须来自持久状态，不能由本地乐观状态伪造。

## 7. 度量与复盘

上线后记录以下最小事件：`project_created`、`blueprint_confirmed`、`chapter_plan_confirmed`、`draft_started`、`draft_completed`、`fact_change_resolved`、`review_finding_resolved`、`chapter_finalized`、`run_recovered`、`export_completed`、`adaptation_started`、`adaptation_source_snapshotted`、`adaptation_decision_resolved`、`screenplay_scene_generated`、`source_scene_mapping_reviewed`。事件必须附带作品/章节或场景/版本上下文和结果，不记录正文或敏感原文。

每周复盘：首章完成率、从首页到继续创作的时间、生成/定稿成功率、事实裁决完成率、恢复成功率、导出完成率，以及按问题类型分组的退出/重试率。任何“用户找不到功能”问题先检查导航路径和文案，再归因为培训或用户能力。
