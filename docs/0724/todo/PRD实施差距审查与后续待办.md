## P0 待办

### P0-01 作者正文编辑与不可变修订

优先级：最高。依赖：无。覆盖：M0-04、AC-04、AC-06、33.1“直接编辑正文”。

现状：工作台用只读 `Textarea` 展示 `StudioChapterRevision.content`，没有正文保存 API。

实施项：

1. 新增“从当前草稿创建作者修订”的 Zod/ts-rest API，输入为完整正文和可选编辑摘要；禁止原地更新历史正文。
2. 新修订保存 `source=author`、`sourceRevisionId`、内容哈希、字数和版本号，并切换草稿当前指针。
3. 前端改为编辑器状态，采用 750 ms 防抖保存，显示保存时间、网络失败和离开页面保护。
4. 已定稿修订只读；编辑已定稿内容必须先创建新的草稿修订。

完成定义：作者能编辑 AI 草稿、刷新后恢复编辑结果、比较 AI/作者版本，并只能对当前草稿定稿。

### P0-02 定稿事实的事务边界校正

优先级：最高。依赖：P0-01。覆盖：M0-05/M0-06、AC-05。

现状：`resolveFactChange` 接受建议时立即修改 `StudioFact`；`finalizeChapterRevision` 仅检查是否还有 `PROPOSED` 建议。这样事实写入不与章节定稿、摘要任务和索引任务构成同一恢复单元。

实施项：

1. 产品和数据模型明确“接受”是否仅表示待定稿接受，建议增加 `ACCEPTED_PENDING_FINALIZATION` 或等价状态。
2. 在定稿事务中统一应用该修订已接受的事实变化、切换定稿指针、创建摘要/索引 outbox 任务和审计记录。
3. 对已发布的立即写入事实数据制定兼容迁移和回填规则；不得删除历史事实或裁决。
4. 为重复提交、并发裁决和事务失败补充幂等键、唯一约束和测试。

完成定义：任一数据库写入失败时，章节定稿状态、定稿指针和事实层不会产生部分提交。

### P0-03 Python 可恢复任务与阶段事件

优先级：最高。依赖：P0-02 的 outbox 契约。覆盖：AC-03、AC-07、W3/W4。

现状：Python Runtime 使用进程内 `jobs`，NestJS 轮询时依赖该内存状态；检查点文件没有恢复消费器。

实施项：

1. 为生成、摘要和索引定义持久化 Run/Task 状态、尝试次数、阶段事件、输入/产物校验和与错误分类。
2. Runtime 采用可重启 worker/队列，启动时扫描可恢复检查点；NestJS 只读取持久状态并下发受控任务。
3. 实现摘要和检索索引任务：成功回写 `completed`，失败回写 `failed` 与可重试原因；索引失败不得阻断已安全提交的定稿。
4. 提供恢复/重试 API 和任务中心查询；前端展示“可恢复”“失败”“已补偿”状态。

完成定义：杀掉 Python 进程后可从最后成功阶段恢复，不重复创建章节修订或事实；可演示 AC-03、AC-07。

### P0-04 结构化审校与硬事实闸

优先级：最高。依赖：P0-01、P0-02。覆盖：M0-07、AC-06、AC-09。

现状：不存在 `ReviewFinding` 数据模型、规则执行、裁决 API 或 UI。

实施项：

1. 新增 `ReviewFinding`、严重度、状态、规则 ID、关联事实、章节修订、正文证据范围、建议动作和裁决原因。
2. Python 先实现确定性硬事实检查，再接入 LLM 软审校；只允许 P0 硬问题阻断定稿。
3. NestJS 保存审校运行与结果，提供查询、接受/忽略/有意变更裁决 API。
4. 工作台展示问题、证据和跳转正文位置；定稿按钮显示准确阻断原因。

完成定义：可构造一个事实冲突案例，系统定位对象与证据，并要求作者修改正文、改设定或记录有意变更。

### P0-05 定稿恢复、并发控制与审计

优先级：最高。依赖：P0-02、P0-03。覆盖：M0-06、AC-07、36.3。

现状：`StudioChapterFinalization` 只包含 `finalized/pending`，没有 `finalizing/failed/recoverable` 状态；Studio 模块没有写入 `AuditLog`。

实施项：

1. 扩展定稿状态机为 `pending/finalizing/finalized/failed/recoverable`，记录恢复点、错误、尝试次数和操作者。
2. 在事务内使用版本/状态条件或锁避免同章并发定稿；重复请求返回同一结果。
3. 写入项目创建、蓝图确认、正文修订、事实裁决、定稿、恢复和回滚审计事件。
4. 为故障注入增加事务回滚、任务补偿、重复请求和并发请求测试。

完成定义：任何异常均能给作者显示真实状态，审计可回溯操作者、输入版本和影响范围，不会出现假成功。

### P0-06 定稿与蓝图回滚

优先级：高。依赖：P0-05。覆盖：M0-08、AC-08。

现状：只支持草稿指针恢复；没有蓝图当前指针历史恢复，也不能将历史定稿作为新的当前定稿。

实施项：

1. 分离“查看历史”“恢复草稿”“恢复定稿”命令，并以新指针/新恢复事件实现，不删除旧版本。
2. 为蓝图增加恢复 API；受影响章节与计划标记为需复核。
3. 回滚前计算章节、事实、摘要、索引的影响范围，前端做二次确认。
4. 后续生成只使用恢复后的当前定稿/蓝图指针，保留完整谱系。

完成定义：可从历史定稿恢复并生成后续章节；历史版本仍可读，且上下文不会混入被替代版本。
